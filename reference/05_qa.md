# 05 · 三轨 QA

所有脚本都在项目目录里跑，产物放进 `qa/<round>/`。每轮结束后在 `qa/qa-report.md` 追加一节：做了什么、证据路径、结论、没测的项目。

## 环境
- `@playwright/test` 钉在 1.63.0。用 `npm test` 和 `npm run qa:*`，不要裸跑 `npx playwright` 或 `npx` 去拉另一个版本。
- Playwright 自带的浏览器下载失败时，设置 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 指向本机的 Chrome 或 chromium（例如 `/usr/bin/google-chrome`，或 `C:\Users\…\chrome.exe`）。额外参数用 `PLAYWRIGHT_CHROMIUM_ARGS`。
- Node 不在 PATH 里时，用完整路径调用。
- 胶片、逐帧 MP4、总览图需要 ffmpeg 和 ffprobe。
- 测试标题如果写在单引号里，标题中的撇号会让 spec 解析失败，现象是 “No tests found”。改完跑 `npm test -- --list`。
- 全片 60fps 录制会跑很久。证据跑全片；`--only` / `--no-video` 只用于查看。看图工具会按路径缓存，每一轮预览用新文件名（`qa-preview` 会加上批次号）。

## 轨 1 · 静态
`node scripts/qa-shots.mjs <round> [--views 1920x1080,1366x768,1280x720,1024x768] [--only S03-2,S05-4] [--query palette=x]`
- 1920 视口下每一步都截图，其他视口只截每页的最后一步，并生成总览图 `contact-<WxH>.png`。非 16:9 的尺寸用来看黑边，不代替下面的测量。
- 自动检查：元素是否超出舞台、文字盒子是否重叠、是否被裁切，以及控制台报错、页面报错、失败的请求。这是盒子级的第二意见。`data-bleed` / `data-edge` 不记出界。
- **预期噪音：** 视频预加载时，翻页或关页会产生 `<视频>.mp4 net::ERR_ABORTED`，属于正常现象。
- **必须亲眼看总览图：** 焦点、断行、裁切、文字和图片冲突、标签是否看得清、相邻页是否连贯。截图只能证明静态状态。相邻两页如果能对调构图，其中一页是模板。

## 轨 1b · 布局测量（门）
`npm run qa:layout`、`qa:layout:static`、`qa:layout:mid`、`qa:type`。四个 16:9 尺寸、每一步、PDF 终态、动画中段，外加阅读文字 ≥ 22px、任何字 ≥ 18px。`--gate` 时必须 0 条，故意的重叠用标记声明并写进 `qa/layout-exceptions.md`。阈值、误报和「0 条不能是空的」见 `08_layout_motion_qc.md`。

`npm run qa:design` 拦住半调 / 点状遮罩，并警告橙 + 蓝占位配色、等宽标题和 SVG 素材。

`npm run qa:gate` 把布局、终态、中段、字号和设计护栏串起来。`npm run release` 会先跑它。

## 轨 2 · 动态
`node scripts/qa-motion.mjs <round> [--from S03 --to S05]`：录一段 1280×720 的真实操作（逐步按 Next），每按一次截一张胶片条（10 帧，每帧相隔 100 ms），另外包括快速连按 5 次和右键退回。给人眼看，不代替逐帧测量。

`npm run qa:run -- <目录> [--gate] [--no-video] [--overlap 150:250] [--reduced]`：60fps 虚拟时间，记 snap / pop / 翻页重叠，并压出 `full-run.mp4`（1920×1080，h264，yuv420p，tv 范围，ffprobe 核对）。`npm run qa:handoff -- <out.json> [--gate]` 查旧字是否压在新字上。单次按键用 `qa:frames` 和 `qa:strip`。脚手架默认转场不是 200ms 手递手；采用按元素离场之后再打开 `--overlap` 和 handoff 的门。见 `08_layout_motion_qc.md`。
- **看胶片条时问：**
  - 视线是否被正确引导？
  - 有没有跳位、闪白、空帧、上一页残留？
  - flood 是否从一条线长出来、新页面的内容是否等铺满之后才出现？
  - 阶梯式动作是否只增不减？
- **本项目抓到的问题：** 带 `data-no-fade` 的结论页画框，在 day→night 的 flood 之前就盖在旧页面上了。修法是去掉 `data-no-fade`，或者给它配一个自己的入场动画。
- 音频要另外验收。录屏不等于听过；没人听过就标 `NOT_TESTED`，并写明谁、用什么设备听过。

## 轨 2b · 媒体
`node scripts/qa-media.mjs <round>`：对每个配了文件的视频槽检查以下几点：
- 元数据能加载，不会自动播放；
- 播放时外框元素退场；
- 按一次 Next 不会停，按第二次才停并前进；
- 自然播完后海报回来。

`qa-media` 用的是 Playwright 浏览器，视频真正的声画质量要在 demo 那边单独验收。

## 轨 3 · 工程与现场可靠性
- `npm test`：17 项通用测试（含页脚计数、布局检查器能抓到人为叠字、计数配方落在印好的数字上），外加讲稿差异和分镜配方次数的单元测试。项目有特有行为时（自定义转场、特殊页）要补测试。
- `node scripts/verify-dist.mjs <round> [--root 目录]`：
  - 新开浏览器上下文，拦掉所有非本地请求，分别用 `file://` 和 `http` 冷启动；
  - 走遍每一页每一步，加载每个视频的元数据，打开演讲者窗口并从那里操作；
  - 刻意设成 `reducedMotion: 'reduce'`，以证明系统设置不会影响动效；
  - 检查包里没有漏文件，也没有混进 node_modules、qa 等不该带的东西。
- 解压后的包也要跑一遍：`powershell Expand-Archive <zip> <临时目录>`（和 Explorer 用的是同一种解压），再 `verify-dist --root <临时目录>\<name>`。
- **只能在现场才验证得了的：** 投影距离下的可读性、翻页笔、扬声器、教室电脑的浏览器版本和系统设置。在 qa-report 里列为“未测”，并交给讲者排练时检查（`06_delivery.md` 的清单）。

## 问题分级（规范 §P6.4）
- **P0：** 演不了、内容严重错误、泄露隐私、控制完全失效。
- **P1：** 核心文字看不清、重要图缺失、关键动作出错、媒体没有替代方案。
- **P2：** 次要的对齐、裁切、节奏问题。
- **P3：** 润色。

记录格式：页 / 步、证据路径、观察到的现象、等级、根因、最小修复、回归测试。

## 评分（只是辅助，不能当证明）
论证与叙事 20 · 构图与层级 25 · 字体与可读性 15 · 素材与气质 15 · 动效与节奏 15 · 现场可用性 10。每项按 0–5 打分再折算权重，参考目标 ≥ 85。只要有 P0 / P1，分数再高也不算过。没有证据的维度写 `NOT_TESTED`。

## 两轮规则
至少两轮真实审查：第一轮修，第二轮回归。连续改了没有改善，就简化效果或替换不稳定的素材，不要无限循环。修不掉的问题在交付时如实说明。
