# 06 · 交付、教室现场、计时

## 一条龙
`npm run release` 依次执行：
1. `build-notes`：由 notes.js 生成 speaker-notes.md；
2. `export-pdf`：导出 `export/reading.pdf` 和每页预览；
3. `build`：生成 `dist/`，包括 START-HERE、可选的 start-server.cmd、presenter-docs 和备用 PDF；
4. `verify-dist release`：冷启动检查；
5. `package`：生成 `release/`。

产物：
- `release/<package>/`：演示文件夹，就是 dist 的副本；
- `release/<package>.zip`：脚本会核对 zip 里每个文件的大小都和文件夹一致；
- `release/<package>_Presentation.pdf`：**提交用 PDF**，每页都是最终状态（静态模式）。

之后再手动做一次：用 Expand-Archive 把 zip 解压到临时目录，然后 `verify-dist --root` 检查（`05_qa.md`）。

## 提交和现场分开
- **交上去的：** PDF。只有课程要求时才连讲稿一起交。讲稿是给讲者用的，默认不提交。
- **现场用的：** 解压后的整个文件夹。大视频（例如 369 MB）会让 zip 很大，要提醒用户留出拷贝时间、准备足够大的 U 盘。
- **讲者文档：** 演讲备注、跑场表、大纲放在包里的 `presenter-docs/`，观众窗口不会加载它们。

## 教室现场清单（2026-10 实际遇到的）
| 现象 | 原因 | 处理 |
|---|---|---|
| 点 start-server 后浏览器显示“无法访问” | 学校电脑没装 Node.js。旧版脚本还先开浏览器、后启服务器 | **不需要服务器**：解压后双击 `index.html`。脚手架的 start-server.cmd 会先检查有没有 Node，没有就提示改用 index.html |
| 页面白底黑字、没有排版和图片 | 在压缩包里直接双击打开（Windows 只临时取出被点的那一个文件），或者文件没拷全 | 右键压缩包 → 全部解压缩，再打开解压出来的文件夹 |
| 动效和自己电脑上不一样（S05 的屏幕效果不见了） | 系统关了“显示动画”导致自动减弱；减弱的选择按地址记住，`file://` 和 `http` 分开记 | 脚手架已改为每次启动都是完整动效，不跟随系统也不记忆（`03_design_motion.md`）；临时处理是按 A |
| 链接打不开 | 参考文献链接需要联网；原来还会在原标签页打开，导致离开演示 | 脚手架让所有外链都在新标签页打开；现场没网就不要点 |
| 默认浏览器是 IE 或 360，排版乱 | 不支持 color-mix 等新特性 | 右键 index.html → 打开方式 → Chrome 或 Edge |
| 弹窗被拦截，演讲者窗口打不开 | 浏览器拦截了弹窗 | 允许弹窗，或者在同一个浏览器里另开一个窗口打开 presenter.html（这种方式只在通过 http 打开时会自动连上） |
| 全屏被拒绝 | 浏览器策略 | 按 F11 |
| 视频不播放或没有声音 | 自动播放被拦截，或者是声音设备的问题 | 点 Play；不要当场排查，直接按 → 继续讲（海报和口述能撑住开场） |

在现场就日志、截图拿不到的情况下：给出最可能的原因和用户马上能做的操作，并请用户描述看到的现象（白底无排版 / 排版乱 / 动效少 / 无法访问）。用户拒绝某个修复方向时，立即停下，换方向。

## 计时与短路线
- **估算：** 讲话部分按每分钟约 140 个英文词，加上媒体时长，再加约 30 秒翻页和停顿。
- **实例：** 本项目讲稿约 1,400 词，加上 2:40 的 demo，完整版约 13 分钟；短路线跳过 3 页后约 10.5 分钟。
- **超时就删内容：** 时限装不下时，优先删重复的论据和可选页，不要把动画加速到看不清。
- **短路线：** 在 `content.js` 里把可跳过的页标 `optional: true`，演讲者窗口会把它们显示成虚线；在 `run-of-show.md` 里写出每处跳过要用的衔接句。

## 交接
`handoff.md` 每次都要更新：阶段状态表、不能改动的约束、待用户处理的事项、环境说明、最后运行的命令、下一步。`README.md` 里只写**实际验证过**的启动方式，并分开写 `file://`、本地服务器、构建后预览三种。
